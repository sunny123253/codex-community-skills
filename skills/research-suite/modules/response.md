# 修回回应与投稿往来

用户要求回复文本时交付完整可审阅的回复，不能只给建议。真实审稿意见与正文里的假想反对意见分开处理：回复信需要直接回答实际关切。

## 从来信到修订计划

先提取编辑要求、稿件信息、决定类型、审稿边界、截止日期和文件要求。把编辑与审稿条目分别编号，保留原文与层级。按误解、证据不足、新颖性、比较/对照、范围、方法/理论、语言等实际关切分类。

对每项判断需要澄清、补充分析/实验、修改主张、补文献或有依据地不同意。先完成能从现有材料确定的工作，只有缺失事实才能向用户提问。新增实验结果、完成的修改和承诺分开，不能写“我们已补充”而实际未做。

## 回复结构

直接回应关切 → 给出证据或具体解释 → 说明实际修改及位置。礼貌、克制，不说“审稿人误解了”来推卸写作责任。已有论据就明确陈述，不堆感谢与自我辩护；没有证据就不编解释。

意见冲突或实验不可行时，说明科学依据和可做的替代工作，保留对中心结论真实重要的限制。不要仅为维持强势语气删去必要承认。按关注点和论据选择回应策略，不推断审稿人的人格，不用心态分群统计预测涨分或接收。

## 具体资源与交付

根据请求读取 [修回格式、困难情形与模板](../references/resources.md#审阅与修回资源)。编辑稿件时保留备份；用户需要标红、斜体引述或 LaTeX 分页时沿用对应模板。模板中的缺失事实保持显式占位，不伪造稿号、行号、日期和新结果。

核对所有条目已回应，每项完成的改动能追溯到稿件、图表、补充材料或明确路径。交付逐点回复、要求的 cover letter 与修改文本，以及仍需用户数据的短说明。草稿与可提交状态按实际内容说明，不以措辞完美替代缺失证据。

本模块起草与修改，不自动发送邮件、提交修订或联系编辑。
